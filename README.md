# DevSecOps Security Pipeline Demo

Небольшое CLI-приложение для демонстрации проверок безопасности Python-кода
в CI/CD. Сейчас приложение проверяет пароль по простой локальной политике:
длина от 12 символов, строчные и заглавные буквы, цифра и специальный символ.

Это учебная проверка состава пароля, а не оценка его реальной стойкости.
Пароль вводится скрыто и не выводится, не сохраняется и не отправляется по сети.

## Установка

Из корня проекта выполните в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade "pip>=26.2"
python -m pip install -r requirements.txt
```

## Запуск

```powershell
python -m security_pipeline
```

Также доступна установленная команда:

```powershell
security-pipeline
```

При корректном пароле приложение завершается с кодом `0`; при несоответствии
политике — с кодом `1`.

## Проверки безопасности

После активации виртуального окружения локальные команды для проверок:

```powershell
python -m pytest
bandit -c pyproject.toml -r src
pip-audit --local --skip-editable
```

`pytest` запускает автоматические тесты, а Bandit выполняет статический анализ
исходного Python-кода. `pip-audit --local --skip-editable` (SCA, анализ состава
программного обеспечения) проверяет установленные пакеты активного окружения
проекта на известные уязвимости по данным Python Packaging Advisory Database.
Перед запуском активируйте `.venv`, как показано в разделе установки: так
проверяется окружение проекта, а не произвольная системная установка Python.
Флаг `--skip-editable` исключает из запроса к базе само локально установленное
editable-приложение, которого нет в PyPI; установленные зависимости и
инструменты разработки по-прежнему проверяются.

Конфигурация pytest, Bandit и список инструментов разработки находятся в
`pyproject.toml`; `requirements.txt` устанавливает проект и эти инструменты.

## Отчёты аудита

Каталог `security-reports/` содержит исходный отчёт с уязвимостями до обновления
инструментов и отчёт после обновления. Это исторические снимки для демонстрации
исправления, а не текущий результат проверки; актуальный аудит выполняется
workflow при каждом `push` и `pull_request`.

## GitHub Actions

Workflow `.github/workflows/security.yml` автоматически запускается при каждом
`push` и `pull_request`. Он использует Python 3.13, создаёт изолированное
виртуальное окружение, устанавливает зависимости из `requirements.txt`, затем
последовательно выполняет pytest, Bandit и pip-audit. Ошибка любой команды
завершает workflow неуспешно. Для workflow предоставлено только право чтения
содержимого репозитория.
